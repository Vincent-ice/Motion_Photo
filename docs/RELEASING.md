# Releasing Motion Photo Maker

This document describes the stable release process. Development artifacts are not official releases.

## 1. Create a persistent release keystore

Create the keystore once and keep an offline backup. **Never commit the `.jks` file or its passwords.**

```bash
keytool -genkeypair -v \
  -keystore motion-photo-release.jks \
  -alias motionphoto \
  -keyalg RSA \
  -keysize 4096 \
  -validity 10000
```

Losing this key means future builds cannot update an installed APK signed with the old key.

## 2. Add GitHub repository secrets

Repository → **Settings → Secrets and variables → Actions → New repository secret**.

Required secrets:

| Secret | Value |
| --- | --- |
| `RELEASE_KEYSTORE_BASE64` | Base64 encoded contents of the `.jks` file |
| `RELEASE_STORE_PASSWORD` | Keystore password |
| `RELEASE_KEY_ALIAS` | Key alias, e.g. `motionphoto` |
| `RELEASE_KEY_PASSWORD` | Key password |

Linux:

```bash
base64 -w 0 motion-photo-release.jks > keystore.base64
```

macOS:

```bash
base64 < motion-photo-release.jks > keystore.base64
```

PowerShell:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("motion-photo-release.jks")) | Set-Clipboard
```

## 3. Prepare a stable version

All feature work should be verified on `develop` first. Before release:

1. Merge the verified changes to `main`.
2. Update `versionName` and `versionCode` in `app/build.gradle.kts`.
3. Move the relevant entries from `CHANGELOG.md` → `Unreleased` into a dated version section.
4. Confirm `THIRD_PARTY_NOTICES.md` if dependencies changed.
5. Confirm the `main` CI build is green.

Version example:

```kotlin
versionCode = 11
versionName = "0.1.1"
```

## 4. Publish

The tag must exactly be `v` + `versionName`.

```bash
git checkout main
git pull --ff-only
git tag v0.1.1
git push origin v0.1.1
```

The `Release` GitHub Actions workflow then:

- validates `v0.1.1` ↔ `versionName = "0.1.1"`;
- restores the signing keystore from repository secrets;
- builds `assembleRelease`;
- verifies the APK signature with Android `apksigner`;
- generates `SHA256SUMS.txt`;
- creates the GitHub Release page;
- uploads `MotionPhotoMaker-<version>.apk` and `SHA256SUMS.txt`.

Release notes are generated by GitHub using `.github/release.yml` and merged pull requests.

## 5. Verify the published release

After the workflow completes:

1. Open the repository **Releases** page.
2. Download the APK and `SHA256SUMS.txt`.
3. Check the SHA-256 value.
4. Install over the previous stable release to confirm signing continuity.
5. Generate at least one Motion Photo and verify it in the system gallery and WeChat.

Linux/macOS:

```bash
sha256sum -c SHA256SUMS.txt
```

## Development builds

`.github/workflows/build-apk.yml` builds debug APKs from `develop` and pull requests. These artifacts are test builds only; they are intentionally separate from signed stable releases.

## Security notes

- Never print signing secrets in workflow logs.
- Never store the keystore in Git, Releases, Actions artifacts, or chat attachments.
- Keep at least one encrypted offline backup of the release keystore.
- Rotate ordinary repository credentials when needed, but do not rotate the Android signing key unless you intentionally migrate the app identity/signing scheme.
